# AI 编程与验收

用 AI 写生产代码，难点已经从"能不能写出来"变成了"怎么确认它写对了"。这个板块记录我自己踩过的坑：需求要怎么写才不留歧义，交付物要怎么验证才不算自欺。

## 这个板块写什么

- [把需求写给 AI：一份秒杀需求的返工记录](./requirement.md) —— 四个缺陷全是需求漏项，不是代码写错
- [6 轮压测和 2 个 P0：AI 写的代码怎么验收](./acceptance.md) —— 压测、故障演练，以及我自己犯的三个验证错误

## 三条原则

1. **需求文档是验收标准的载体** —— 写不出失败语义矩阵，说明需求还没想清楚，AI 只会填一个通用默认。
2. **"已自测通过"不构成证据** —— 唯一能证明并发正确性的是对账数字，不是代码审查，也不是它自己的说明。
3. **怀疑自己的验证方法，先于怀疑代码** —— 我三次误判全是"没验证就以为验证了"，AI 不会替你怀疑这一步。

成本没有消失，只是从"实现"移到了"把话说清楚"和"证明它对"这两件事上。
