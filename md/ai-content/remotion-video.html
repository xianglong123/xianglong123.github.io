用 Remotion 做一条抖音视频：从文案到渲染的完整过程

2026-11-24 · AI 内容实验 · 1080×1920 / 41.5 秒 / 5.2MB

成片：Remotion 开源项目介绍（竖屏）

为什么用代码做视频

剪一条 30 秒的竖屏视频，手工流程大概是：找素材、排版、配字幕、调时间轴、导出。改一个数字就得重来一遍。如果要做系列内容，一天一条，这些动作会重复到让人放弃。

Remotion 换了个思路：把每一帧当成一个 React 组件，用代码描述画面，渲染器负责把组件树变成 mp4。好处是具体可感的：

  • 改数字 = 改画面，不用打开剪辑软件
  • 一套组件可以重复用，风格不会跑偏
  • 渲染可以跑在脚本里，不需要人守着进度条

这条片子就是全代码生成的：画面、字幕、动效、配音全部由脚本产出，没有任何手工剪辑环节。

一、先定结构，再写文案

竖屏短视频的死穴是前 3 秒。所以结构不按「项目介绍」的常规顺序（先讲这是什么），而是先抛一个和观众有关的痛点，再进项目。整条固定成 8 段，长度 41 秒：

时间段落作用
0–4s痛点钩子留人，不给结论
4–7s项目卡仓库名 / star / 语言
7–11s核心机制一句话讲清它是什么
11–20s三个卖点我实际用上的地方
20–26s真实界面证明东西是真的
26–32s一个坑讲清许可，建立信任
32–36s适合谁让目标观众对号入座
36–41s追更钩子预告下一条，换关注
这个结构可以复制到任何「工具/项目介绍」的选题上：换掉事实，骨架不动。这是能把成本压下来的前提。

完整旁白文案（约 215 字，念完 40 秒）：

// caption.md
你剪一条三十秒的视频要多久？我用代码，两分半就渲染完一条。
这个项目叫 Remotion，七万五千星，用 React 写视频。
它干的事很直接：一段 mp4，就是一段代码，每一帧都是一个 React 组件。
三个我真正用上的地方。不用打开剪辑软件，改个数字就能重出一版。
同一套模板，换掉文案，就是一条新的。渲染全自动，晚上跑，白天发。
看这个界面，左边是文件列表，中间是画面，底下是时间轴。
它本质上是能写代码的剪辑软件。
但有个坑得先说清楚：它不是开源软件。自己用来做视频免费，
批量出片当服务卖，要按次付费。
适合谁？做矩阵号的，要批量做数据视频的，不想学 AE 的程序员。
下期我拆一个更狠的：同样这套东西，做一条六十秒的讲解片。

二、配音：TTS + 停顿检测

配音走的是文本转语音，一次生成整段 wav（40kHz / 双声道），大约 9MB。拿到音频后要做的事是把画面时间轴对齐到语音。做法是先测静音段：

ffmpeg -i voice.wav -af silencedetect=noise=-36dB:d=0.18 -f null -

上一次做黎曼猜想那条时，这个方法很好用：句与句之间有 0.5–1.8 秒的自然停顿，直接拿停顿点当镜头切点，画面和语音几乎严丝合缝。

这次翻了车。因为提示词里写了「语速快」，成片 40 秒读完 215 字，句子之间的间隙全部小于 0.3 秒，用 0.4 秒阈值做包络检测，一个句界都没抓到。最后只能按字数比例分配时间轴，实际偏差在 0.5 秒以内，能看，但不精确。

结论是：要逐句对齐，就在提示词里明确要求「每个句号后停顿半秒以上」；要快节奏，就得接受按比例估算。这两个目标在 TTS 上是矛盾的，得先选一个。

三、画面：组件 + 时间轴常量

8 段各写成一个组件，用 <Sequence> 按帧区间挂上去。所有时间点集中在一个常量里，改节奏只改这一处：

const T = {
  hook:     [0, 116],      // 0–3.9s
  repo:     [116, 207],    // 项目卡
  mech:     [207, 339],    // 机制
  points:   [339, 612],    // 三个卖点
  shot:     [612, 777],    // 真实截图
  caveat:   [777, 966],    // 许可坑
  audience: [966, 1077],   // 适合谁
  outro:    [1077, 1245],  // 追更
};

几个关键实现：

  • 痛点那 4 秒：计时器从 0:00 滚到 2:25，数字来自实测渲染耗时 145 秒，不是编的。
  • 机制那 4 秒：左边一段 JSX 代码块，右边四个渐变帧块，中间一个箭头。「一段 mp4 就是一段代码」用画面讲，不靠字。
  • 截图那 6 秒：真实 Studio 界面截图放进圆角框，scale 1.0 → 1.13 做缓慢推镜，下面三个 chip 标注「左 / 中 / 底」。
  • 许可那 6 秒：两张对比卡，左「免费」白字，右「$0.01/次」红字，视觉上直接分出性质。

渲染命令：

npx remotion render src/index.jsx RemotionTopic out.mp4 --codec=h264 --crf=20

四、模板化：数据驱动，而不是复制代码

这条片子真正的产出不是 mp4，是模板。所有会变的内容抽到一个数据文件里，下次换项目只改这里：

export const remotionTopicData = {
  voice: 'remotion-topic.wav',
  hook: ['你剪一条 30 秒的视频，要多久？', '我用代码，只花', ...],
  repo: 'remotion-dev/remotion',
  oneLiner: '用 React 写视频',
  lang: 'TypeScript',
  points: [
    { title: '改个数字，重出一版', desc: '不用打开剪辑软件，参数全在代码里' },
    { title: '一套模板，换文案就是新片', desc: '组件复用，风格永远不会跑偏' },
    { title: '渲染全自动', desc: '晚上跑，白天发，不用守着进度条' },
  ],
  audience: ['做矩阵号的', '要批量做数据视频的', '不想学 AE 的程序员'],
};

下次要出片，只剩三步：换 data 文件里的字段、换一张真实截图、重跑一次 TTS。人工时间从「剪一条视频」降到「审一段文案」。

指标数值

人工耗时选项目 + 审文案，约 10 分钟

算下来一条 40 秒的视频占机器 3.6 分钟。一天 10 条也只要 36 分钟机时，完全可以在夜间批量跑。

Remotion 不是 OSI 开源软件，是 source-available 许可：个人或 3 人以下小团队自己做视频免费；自动化批量出片作为服务对外售卖，官方口径是每次渲染 $0.01、月最低 $100，5.0 起还会强制上报 licenseKey。自用没问题，做成产品卖之前先读许可。

六、踩过的坑

  1. Root.jsx 返回多个 <Composition> 必须包 Fragment。直接并列两个会被 esbuild 判定为语法错误，报 Expected ")" but found "id"，而且报错位置在 Root.jsx 而不在出错的那一行。
  2. 淡出不要用「透明度归零」。第一版把已经过去的格子渐隐到透明，结果画面上半部分整片空白，看起来像渲染失败。正确做法是给每格留一个深色底，只让上层色块淡出，矩阵结构始终在。
  3. 中文大标题要手动断行。竖屏宽度下，靠自动换行会把句子断成「你剪一条 30 秒的视频，要 / 多久？」。要么给 white-space: pre-line 手动插换行，要么收窄字号。
  4. 别在竖屏底部放内容。抖音的文案区和按钮会压住下面 200px，字幕固定在 bottom: 168px 比较安全。
